# Curriculum contracts

Schema files use JSON Schema Draft 2020-12 with closed objects and required fields. Run npm run schema. Cross-reference, uniqueness, choice-range and physical review checks require separate tests/review; JSON Schema alone cannot establish them.

- chapter.schema.json: version, stable chapter/workshop/stage IDs, honest status and scope note, original lessons and exercises. Lesson steps declare stable entity IDs to highlight; each lesson has a rule, memory cue, trap and application. Each stage declares type, answer, explanation and exactly two progressive hints. Choice answers are zero-based integer option indices; selection answers are exact sets of entity IDs. Number answers have finite JSON numbers, nonnegative tolerance and explicit unit metadata. Text is case-sensitive unless explicitly declared otherwise; aliases must be deliberate. A stage may override the workshop asset.
- assets.schema.json: typed concept schematics with string IDs, node labels/coordinates, edge endpoints, context and scientific review note. The required visual.type chooses an original SVG physical illustration or process schematic in dev/src/visuals.mjs. The four stable node IDs bind labels, structural focus and exact selection answers. These are simplified physical illustrations, not exact scale drawings or experimental measurements. Learn may animate a qualitative process; active practice and blind SVGs are static and have no teaching focus.
- catalog.schema.json: 12 ordered chapter entries using actual source headings, with planned/pilot/implemented status and section outlines. A planned catalog entry is not implemented content.

When a substantially new assessment replaces an existing one, change the workshop ID to invalidate prior completion. All implemented chapters retain an explicit independent-science-review-pending note; implementation status never implies scientific sign-off. Future data types (measured plots, calibrated apparatus) need explicit schema/context conventions and their own tests rather than pretending to be concept schematics.

Teaching cards (`coreRule`, `memoryCue`, `traps`, `application`) each contain a concept-specific `title` and 2–4 original `paragraphs`. Text is escaped at rendering; HTML is not supported. Use the second paragraph for a concrete contrast, worked example or bounded inference. Cues must explain their mapping; traps must correct the tempting inference; applications must state assumptions and distinguish hypothetical cases from data. Native colored details/summary cards remain exclusive to Learn & Explore.
